terraform-multi-az-vpc

One VPC.
Two availability zones.

If one zone goes down, the other keeps serving. Scroll to build it.

Subnets

Public in front.
Private behind.

Only the internet gateway, load balancer, and NAT gateways face the internet. Everything else sits in private subnets.

Load balancing

One load balancer.
Every zone.

An Application Load Balancer spans both zones and sends traffic only to healthy instances.

Compute

Instances that
replace themselves.

An Auto Scaling group runs EC2 across both private subnets and replaces any instance that fails a health check.

Access

No SSH. No bastion.
No key pairs.

Instances are reached through SSM Session Manager with instance profiles, so there's no port 22 to open and no key to leak.

State

State that
can't collide.

Terraform state lives in S3 with a DynamoDB lock, so two changes can never overwrite each other. View the code ›

terraform-cicd-github-actions

Deploys without
a single stored key.

GitHub's OIDC provider hands the pipeline short-lived AWS credentials. Nothing secret is ever saved in the repository.

1

Open a pull request

A change to the Terraform code starts the workflow.

2

Plan posts to the PR

terraform plan runs with a read-only role and comments the diff.

3

Approval gate

A required reviewer signs off before anything changes.

4

Apply on merge

Only main can assume the write role and run apply.

5

Drift check

A scheduled run opens an issue if AWS no longer matches the code.

Pull requests

Read-only role

Trust-policy conditions limit it to pull request runs. It can plan, but it can never apply.

Main branch

Write role

Its trust policy is scoped to the main branch, so no other branch can change infrastructure.
